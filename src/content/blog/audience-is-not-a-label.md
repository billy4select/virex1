faq:
  - q: 為什麼只寫「25 到 35 歲上班族」不算有效的受眾分析？
    a: 人口統計標籤無法告訴你顧客為什麼買或不買。有效的受眾分析要拆解「需求出現的情境」、「他想完成的任務」、「遲遲沒行動的障礙」與「目前的替代方案」，才能直接指導產品、文案與通路決策。
  - q: 朋友說「這點子不錯，出了我會買」，算市場需求驗證嗎？
    a: 不算。口頭承諾的成本太低，朋友支持多半是情感而非市場。至少要讓陌生潛在顧客付出時間、留下聯絡資料、付訂金，或真的使用手動交付的最小版本，才算初步驗證。
  - q: 做需求訪談時，為什麼不要問「你會不會買、願意付多少」？
    a: 因為人對未來的假設性意願往往過於樂觀。改問「過去的具體行為」——上一次何時遇到這問題、當時怎麼解、花了多少時間或錢、哪一步最麻煩——得到的證據才可靠。
  - q: 還沒有完整產品，怎麼用最低成本驗證市場需求？
    a: 先用服務或介紹頁驗證：做一頁說明頁測留單轉換、開小額預售或收訂金（寫清退款條款），或先用人工手動交付一次給 3–5 位早期使用者。連手動交付都沒人要，通常不是產品不夠完整，而是需求還沒成立。

做行銷企劃或開發新產品時，最常踩的兩個坑分別是：把受眾寫成一張身份證（例如「25–35 歲上班族」），以及問朋友「你覺得這點子怎麼樣」就以為市場很大。同樣 35 歲的上班族，有人剛升主管、有人準備轉職，願意付錢的理由天差地遠；而「想要」跟「真的願意掏錢」之間，還隔著急迫性、預算與替代方案。

這篇把**看懂受眾的四要素架構**、**辨識商業機會的五個付費訊號**，以及**做產品前避免自嗨的五個實測驗證方法**整合成一套完整工作流，幫你在花大錢開發或投廣告前，先讓真實顧客用行為回答你。

## 受眾不是標籤：拆解情境、任務、障礙與替代方案

年齡、性別、職業只能用來描述市場規模與設定媒體標籤，無法決定你要講什麼賣點、賣什麼方案。分析任何受眾，先往下拆開這四件事，並直接對照它們會影響哪些決策：

| 受眾分析四要素 | 核心提問 | 直接影響的行銷與產品決策 |
| :--- | :--- | :--- |
| **1. 需求情境** | 發生什麼觸發事件讓他此刻找解方？（例：學英文是為下個月面試還是旅遊） | 產品使用時機、內容選題與曝光通路 |
| **2. 想完成的任務** | 他買單究竟想把哪件事搞定？（例：買筆記工具是為了會後找回決策） | 產品定位、功能優先順序與真實競爭對手 |
| **3. 決策障礙** | 什麼讓他遲遲沒行動？（價格、怕學不會、缺乏信任、需主管同意） | 銷售頁說明順序、試用／案例設計與減輕風險 |
| **4. 現有替代方案** | 不買你的，他現在怎麼硬撐？（Excel、人工、外包、或先忍耐不處理） | 定價上限、差異化切角與轉換成本評估 |

整理完後，把受眾寫成一句**可驗證的付費假設**：

> 當【情境】發生時，【某類人】為了解決【任務／問題】，目前使用【替代方案】、每次付出【時間或金錢成本】，卻卡在【障礙】。如果能提供【具體結果】，他願意付【價格】。

如果這句話裡有任何一格寫不出來，就代表你對受眾的認識還停留在想像階段（更多關於痛點時刻的定義實作，也可以搭配 [行銷從診斷開始：受眾定義章節](/marketing/audience/)）。

## 區分三種需求層級，盯緊五個「真的會付錢」的訊號

商業機會很少是「發明一個全新需求」，而是把一個**已經在花時間或花錢解決的痛點**，換成更省力的解法。先分清顧客說的屬於哪一層：
- **想要**：口頭說「有這個功能不錯」，多半是禮貌或興趣，還沒有行動意願。
- **需要**：問題確實存在，但目前用人工或折衷方案還能忍受，缺乏立刻轉換的推力。
- **願意付錢**：問題有期限、有後果、已經編了預算，這才是真正的商業機會。

判斷一個點子是不是「願意付錢」層級，直接看市場上有沒有出現這五個訊號：
1. **正在用很笨的方法硬撐**：每週手動貼報表、用 Excel 拼客戶資料、花兩小時重複寫信。
2. **已經在花錢解決**：早就買了軟體、外包、顧問或課程，代表預算真實存在。
3. **會主動搜尋、比較與提問**：主動找解法代表進入決策期，他搜的詞就是你的內容起點（延伸見 [SEO 教學：從購買前煩惱找關鍵字](/seo/keywords/)）。
4. **問題有明確期限或後果**：報稅、季度報告、展覽、客戶合約等有死線的任務，付費意願遠高於「有空再說」。
5. **願意先投入低門檻承諾**：願意給資料、接受訪談、試用原型或付小額訂金。

## 訪談要問「過去的行為」，絕不要問「未來的意願」

問潛在客戶「你會不會買？你願意付多少？」幾乎問不出真話，因為人對未來的自己都很樂觀。把訪談問題全部改問**過去已經發生的具體事件**，才能篩出真實需求：

| 容易問出客套假話的問題（避免） | 能挖出真實行為的問題（改這樣問） |
| :--- | :--- |
| 「你覺得我這個點子怎麼樣？」 | 「你上一次遇到這個問題是什麼時候？」 |
| 「如果做出來，你會不會買？」 | 「當時你怎麼解決？花了多少時間或錢？」 |
| 「你希望這個工具多哪些功能？」 | 「整個過程裡，哪一個環節讓你最麻煩？」 |
| 「你願意為這個付多少錢？」 | 「你有比較過其他方案嗎？為什麼最後沒選？」 |

一個人對過去踩坑的細節講得越具體，這個需求的真實度就越高。

## 五個避免自嗨的市場需求實測方法（由低成本到高成本）

在花三個月開發完整產品之前，照以下五個方法由淺入深推進，至少要通過其中兩到三個，才值得繼續加碼投入：

1. **方法一：觀察既有行為**：先爬論壇、社群、商品負評、競品定價與外包市場，找「已經有人在用不完美方式解決」的證據。
2. **方法二：訪談過去行為**：找 5–10 位符合情境的陌生對象，用上一節的過去行為題問出真實成本與卡點。
3. **方法三：做一頁介紹頁測轉換**：寫清楚解決什麼問題、適合誰、交付什麼、價格與下一步，用少量流量觀察留單或預約轉換率（點擊便宜不算數，連留 Email 都困難代表價值主張還沒立住）。
4. **方法四：小額預售或收訂金**：把交付時程與退款條款寫清楚，測試陌生人願不願意真的掏錢表態（務必留意消保與履約誠信）。
5. **方法五：手動交付一個最小版本**：先別寫程式或錄完整課程，找 3–5 位早期客戶用人工與現有工具親手交付一次。這一步雖然累，但會立刻暴露需求、溝通、定價與交付品質的所有盲點。

### 用四格評分表決定要不要往下做

每跑完一輪實測，誠實填完下面四項；若四項都偏低，請先停下來修正客群或需求，千萬別急著繼續做產品：

| 檢驗指標 | 核心檢查問題 |
| :--- | :--- |
| **需求強度** | 這個問題有沒有明確期限、代價或後果？ |
| **付費意願** | 除了朋友捧場外，有沒有陌生人真的付錢或付訂金？ |
| **取得成本** | 找到一位願意付錢的客戶，要花多少時間與廣告費？ |
| **重複與轉介** | 同一位客戶會不會再買，或主動推薦給同行？ |

避開三個最常見的驗證誤區：**別把朋友的鼓勵當驗證**、**別把大市場規模（TAM）當成你拿得到的客群**、**別把一次驗證當成永久有效**。需求成立之後，再接著用 [一門生意為什麼成立？九大問題與獲利結構拆解](/blog/why-business-exists-nine-questions/) 把單筆利潤與護城河算清楚，這門生意才真正站得穩。
