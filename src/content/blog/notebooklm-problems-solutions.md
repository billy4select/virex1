明明照著網路教學把 PDF 和 Excel 丟進 **NotebookLM（Google 現亦稱 Gemini Notebook）**，結果它不是冷冷回你「來源中未提及」，就是吐出一堆中文亂碼，或是寫出來的文字硬得像操作說明書——這是幾乎每個把它放進日常工作兩週後，一定會碰到的卡關時刻。

其實想通它的底層設計，八成問題都很好解：**NotebookLM 為了把 AI 幻覺降到最低，刻意把自己鎖死在「只讀你上傳的純文字層」**。它不像 ChatGPT 會幫你腦補外部知識，對檔案衛生也挑剔得多：只要 PDF 本質是掃描圖檔、Excel 帶著 Windows 舊編碼，或同一個筆記本混了新舊版本草稿，它就會直接失準。

這篇把最常撞到的 7 大痛點、免費版上限與支援格式、免費 OCR 轉換法與 Excel／CSV 轉檔實測整在同一頁，卡關時直接照表排查。

## 常見問題速查表：先對號入座找解法

遇到 NotebookLM 答非所問或不好用時，八成以上都不是模型變笨，而是來源格式、版本混雜或用錯場景。先從下表對照你現在的症狀，再往下看詳細排除步驟。

| 常見症狀 | 背後真正原因 | 最省事解法 |
| :--- | :--- | :--- |
| **PDF 讀不到或變亂碼** | 檔案是掃描圖片（無文字層）或中文編碼異常 | 先用滑鼠反白測試，無文字層就先做免費 OCR 再上傳 |
| **吐出來的文字很硬像說明書** | 系統為降低幻覺緊貼原文，天生缺乏寫作節奏 | 只叫它出「觀點＋證據＋出處」底稿，改寫交給自己或 Claude |
| **問背景概念一直答「未提及」** | 回答被鎖定在已上傳來源，無法向外延伸 | 去外部找靠譜資料存成 PDF 或貼網址，補進同一本筆記本 |
| **複雜表格或圖表數字抓錯** | 多欄跨頁表格轉純文字時容易欄位錯位 | 問出來的數字只當線索，關鍵數據一律點引用回原檔核對 |
| **傳十份檔案卻只引用一兩份** | 問題太寬，系統偷懶只抓字面最相近的段落 | 在左側手動只勾選要比對的 3–4 份檔案並指定交叉比較 |
| **回答太籠統像廢話** | 第一句就問「幫我總結全部資料」 | 改成「先問整體架構，再針對單一區塊追問為什麼」 |
| **舊數字跟新方案混在一起答** | 初版、修改版、最終版全塞在同一本筆記本 | 移出舊版草稿，檔名統一標註 `日期_主題_來源` |

## PDF 讀不到掃描檔？三種免費 OCR 轉換做法與抽查重點

把 PDF 丟進 NotebookLM 卻顯示找不到資料或答非所問，最常見的原因是這份檔案只是一張一張掃描出來的圖片、裡面根本沒有文字層。上傳前花 10 秒測一次反白，必要時先做 OCR 轉換，就能徹底避開這個坑。

### 第一步：判斷你的 PDF 是哪一種

在電腦打開 PDF，拿滑鼠拖曳內文做測試：
- **原生文字檔**：文字可以順利反白、複製貼上到記事本也正常，NotebookLM 直接讀得到。
- **純掃描圖片檔**：點下去像一張大圖、完全選不到字，直接上傳一定會漏讀。
- **混合檔（最容易中招）**：前面目錄選得到字，後面關鍵報表或附錄卻全是截圖，容易讓人誤以為整份都讀進去了。

轉檔之前，先花一分鐘確認手邊有沒有原始 Word、Google 文件或官方電子版 PDF；原始電子檔結構最乾淨，真的找不到再動手做 OCR（光學字元辨識）。

### 第二步：依頁數與機密程度挑免費 OCR 做法

現在要把掃描 PDF 轉出文字層門檻很低，照檔案頁數跟資料敏感度挑最順手的工具就好：

| 免費 OCR 做法 | 最適合的檔案情境 | 繁中辨識表現 | 資料隱私風險 |
| :--- | :--- | :--- | :--- |
| **Google 雲端硬碟轉 Google 文件** | 10–50 頁一般橫排中文 PDF、報告與講義 | 印刷體表現穩定，但複雜表格易跑版 | 低（留在自己 Google 帳號內） |
| **Mac 預覽程式 / Windows 截圖工具** | 只需要複製少數 1–5 頁關鍵段落或截圖 | 單頁複製準確度高、幾乎免重排 | 最低（全程本機離線處理） |
| **專用免費 OCR 工具（如 OCRmyPDF）** | 需要保留原本 PDF 版面並補隱藏文字層 | 視引擎與原始掃描解析度而定 | 線上版有外洩風險；本機版安全 |

- **Google 雲端硬碟（最省事）**：把 PDF 傳上 Google Drive，對檔案按右鍵選「選擇開啟工具 → Google 文件」，系統會自動把圖片文字轉成新的 Google 文件，微調後直接匯入 NotebookLM。
- **系統內建工具（少量頁面最快）**：Mac 預覽程式與 Windows 截圖工具都能直接選取圖片文字，只有幾頁關鍵附錄時直接複製貼到純文字檔最穩。
- **專用 OCR 工具（保留版面）**：像本機版 OCRmyPDF 可在原檔補上一層隱藏文字；切記只要涉及公司內部資料或客戶個資，絕不要隨便丟到來路不明的線上免費 OCR 網站。

### 第三步：轉完必查三個地方，且大檔別轉整份

中文 OCR 轉完不代表百分百無誤，上傳進 NotebookLM 前先抽查三處：
1. **專有名詞與數字**：中文掃描檔極常把 `0` 認成 `O`、把 `1` 認成 `l`，金額或百分比錯一個字，後面分析就會全偏。
2. **多欄表格是否跑版**：複雜表格轉純文字後常會擠成一長串，連哪個數字配哪欄都分不清，重要表格請留原檔對照。
3. **頁首頁尾與註腳**：確認沒有大片重複頁碼或頁尾文字混進正文打斷語意。

如果手上是一份兩百頁的舊報告，你真正要研究的只有其中二十頁，**先把需要的頁數拆出來單獨轉檔**。辨識速度快很多，塞進 NotebookLM 後也不會被無關頁面干擾回答。

## 免費版上限、字數與檔案支援格式速查表（2026）

上傳失敗很多時候不是檔案壞掉，而是撞到單檔上限或丟了原生不支援的格式。先對照 2026 最新規格表：

| 規格項目 | 免費版 | 付費版（Google AI Pro / Workspace 方案） | 實務建議 |
| :--- | :--- | :--- | :--- |
| **每本筆記本來源上限** | 最多 **50 個**來源 | 最多 **300 個**來源 | 來源超過 40 份建議依主題拆本，回答更精準 |
| **單一來源字數上限** | **500,000 字** | **500,000 字** | 一般專書很少超過 15 萬字，多半夠用 |
| **單一檔案大小上限** | **200 MB** | **200 MB**（企業版更高） | 超大 PDF 先壓縮圖片或拆分章節 |
| **原生支援格式** | PDF（含文字層）、Google 文件／簡報、`.txt`、`.md`、公開網頁、有字幕 YouTube、音訊檔（MP3／WAV） | 同左，並放寬每日提問與語音摘要額度 | 加密 PDF、需登入網頁或純掃描圖檔需先轉檔 |

## Excel 與 CSV 亂碼怎麼辦？3 種轉檔與整理實測

很多人把公司報表或客戶問卷直接用 Excel（`.xlsx`）或 CSV 丟進 NotebookLM，結果不是格式不支援，就是中文全變亂碼、欄位全部錯位。原因有兩個：**台灣 Windows Excel 預設匯出的 CSV 是 Big5 編碼**，而且 NotebookLM 天生擅長讀語意段落，不適合算千筆試算表明細。

| 你的試算表類型 | 推薦轉檔解法 | 注意事項 |
| :--- | :--- | :--- |
| **問卷文字回饋、客訴清單**（欄位少、文字多） | 用 Google 試算表另存 **UTF-8 CSV** 或轉成 **Markdown（`.md`）表格** | 千萬別直接用 Windows Excel 預設一般 CSV，否則中文會亂碼 |
| **產品規格表、方案對照表**（5 欄內） | 複製貼進 **Google 文件**再匯入，表頭補 2 行背景說明 | 先取消所有「合併儲存格」，避免欄位錯位 |
| **上千筆訂單或業績明細**（需要加總統計） | **先在試算表跑完樞紐分析**，只把 1–2 頁摘要表轉 PDF／MD 上傳 | 算數字交給試算表，交叉解讀原因再交給 NotebookLM |

## 網頁抓不到內容、YouTube 字幕無法匯入怎麼辦？

除了檔案格式，貼網址（URL）跟 YouTube 連結也是高頻報錯來源，通常原因與解法都很固定：

- **網頁貼上去一直轉圈或抓到空白**：只要該網站需要登入、有付費牆、擋爬蟲，或是靠大量動態腳本才載入內文，NotebookLM 就常抓不到。最快解法是直接在瀏覽器按「列印 → 另存為 PDF」，或複製正文貼到純文字／Google 文件再匯入。
- **YouTube 影片匯入失敗**：NotebookLM 其實不會「看畫面」，它是直接抓影片的**公開字幕檔**（含自動生成字幕）。如果影片設為不公開、剛上傳還沒跑完自動字幕、或作者關閉了字幕功能，就會匯入失敗。建議確認影片有公開字幕再貼，或是先擷取逐字稿轉成 `.txt` 上傳。

## 回答品質與引用異常：六個高頻痛點逐一排除

扣掉掃描檔讀不到之外，日常工作最常讓人想放棄 NotebookLM 的就是下面這六個狀況。每一題都有對應的最小調整動作，不需要重學一套工具。

### 1. 吐出來的文字很硬，沒辦法直接拿來用

叫它把五份報告整理成提案段落，字面都對但句型重複、像說明書，完全沒有觀點跟節奏。這題靠改 Prompt 改善有限，最省力的做法是**不要叫它當寫手**——只要求它列出「觀點、支持證據、原文出處」，核對無誤後帶出來自己改寫，或交給 Claude 順架構（分工方式見 [NotebookLM vs Claude 怎麼分工](/blog/notebooklm-vs-claude-internal-docs/)）。

### 2. 資料裡沒寫的東西，怎麼問都卡住

因為它被鎖死在已上傳的來源裡，遇到報告一筆帶過的前提或基礎名詞，想往外延伸學習它只會回「來源未提及」。不用硬問，直接去外部搜尋把缺的背景資料補齊，存成 PDF 或貼網址補進同一本筆記本就能繼續拆解。

### 3. 複雜表格或圖表數字抓不準

多欄跨頁表格或純長條圖頁面轉成文字後很容易欄位錯位，甚至把 A 產品的價格接到 B 產品身上。碰到要放進報表或簡報的關鍵數據，不要只信回答文字，務必點擊引用編號回原檔核對原始表格。

### 4. 塞了十幾份檔案，回答卻只引用一兩份

檔案一多，問大問題時它很容易偷懶只挑字面最接近的兩份文件回答。解法很直接：在左側來源清單**手動只勾選**本次要對照的那三四份檔案，並在問題裡明確寫出「請逐一比較這幾份來源對某議題的異同」。

### 5. 回答太籠統，看完跟沒看一樣

這幾乎都發生在第一句就問「幫我總結全部資料」。改成先問「這批資料的整體架構可以分成哪幾塊」，再挑不懂的單一區塊一個一個追問為什麼，完整提問句型可以直接套用 [NotebookLM 教學完整指南的五種提問指令](/blog/notebooklm-complete-guide-2026/)。

### 6. 舊資料跟新版本混在一起答

把「初版」「修改版」「最終定案版」全留在同一個筆記本，系統不會自動幫你判別哪一份才算數，常會把去年的舊數字跟今年的新方案混在同一段裡。養成習慣：舊版直接移出筆記本，檔名一律標註日期與來源。

## 什麼時候乾脆換工具，不要硬留在 NotebookLM？

沒有任何一個 AI 工具適合包辦所有工作，遇到不適合的場景硬撐只會浪費時間。把 NotebookLM 留在「消化大量原始資料、查原文出處」這個位置上，看到以下三種需求就直接果斷切換：

| 任務需求 | 為什麼別硬用 NotebookLM | 建議切換的工具 |
| :--- | :--- | :--- |
| **需要最新即時資訊或外部背景** | 被鎖死在已上傳檔案，無法自動補外部知識 | ChatGPT / Gemini 搜尋完，再把靠譜來源存回筆記本 |
| **要寫有觀點、有溫度的長文或提案** | 行文天生偏硬、句型重複，改稿成本高 | 把核對完的事實底稿帶去 Claude 或自行改寫 |
| **需要長期分類、標籤與團隊協作追蹤** | 筆記本定位是專案研究空間，不適合當長期 SOP 資料庫 | 定案後的結論與模板改存 Notion 歸檔 |
