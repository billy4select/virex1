A 版 CTR 是 1.2%，B 版是 1.8%，所以 B 版比較好嗎？

如果兩個版本的受眾、版位、投放時間與預算條件不同，這個比較可能沒有意義。即使條件接近，也要先確認差異是否足以排除隨機波動。

A/B 測試的價值，在於回答一個事先定義的問題，而不是從一堆數字裡挑出看起來比較漂亮的版本。

## 先寫下要驗證的假設

不要只寫「想提高 CTR」。可以更具體一點：

- 目前素材沒有呈現使用情境，加入情境畫面可能讓目標受眾更容易理解產品。
- 目前標題強調功能，改成描述使用者遇到的問題，可能增加相關點擊。
- 目前 CTA 不夠明確，改成具體行動可能讓有需求的人更容易採取下一步。

假設越清楚，測試結果越容易轉化成下一次的判斷。

## 決定這次要比較什麼

如果想知道圖片是否影響點擊，可以保留受眾、文案與 CTA，主要替換圖片。如果想測試不同的整體創意策略，也可以比較兩套完整版本，但結論應該寫成「版本 A 與版本 B 的整體表現不同」，不能直接歸因到其中一個元素。

常見的測試方向包括：

1. **視覺**：產品特寫、使用情境、人物、前後差異。
2. **標題與首句**：功能說明、問題描述、使用成果或具體情境。
3. **CTA**：了解更多、查看方案、立即預約等不同下一步。
4. **訊息切角**：價格、便利性、品質、服務或風險降低。

不必每次都照固定順序測。應該從目前最不確定、也最可能影響結果的地方開始。

## 讓兩個版本有公平的比較條件

盡可能維持相同的受眾條件、投放目標、版位、期間與預算分配。若平台提供實驗功能，優先使用能避免受眾重疊或流量分配偏差的設定。

如果兩個版本在不同日期、不同受眾或不同預算下投放，結果就可能受到外部條件影響。這時候應該把限制寫在測試紀錄裡。

## 不要用固定曝光數當成所有測試的答案

需要多少樣本，會受到原本 CTR、想辨認的差異大小、流量分配與數據波動影響。小流量帳號可能很難在短時間內得到明確結果。

因此不要看到幾百次曝光就宣布勝負，也不要因為某個版本短時間領先就立刻停止另一個版本。測試前先設定觀察期間與判斷方式，避免事後挑選有利的時間區段。

如果流量不足，可以把測試當成方向探索，記錄結果並累積多次觀察，不要把一次小樣本測試當成普遍規律。

## CTR 不是唯一的成功指標

CTR 高，代表更多看到廣告的人點擊了，但不代表這些人真的有購買需求。

至少一起觀察：

- CTR：廣告是否吸引點擊。
- 到站品質：點擊後是否真的載入頁面、停留或繼續瀏覽。
- 轉換率：訪客是否完成預期行動。
- CPA 或 CAC：取得轉換或新客需要多少成本。
- 毛利或有效名單品質：結果是否對生意有價值。

如果 B 版 CTR 較高，卻帶來大量低品質流量，最後的商業結果可能反而比較差。

## 每次測試都留下紀錄

| 欄位 | 記錄內容 |
|---|---|
| 測試問題 | 這次想知道什麼？ |
| 假設 | 為什麼認為修改會有效？ |
| 主要差異 | 兩個版本改了什麼？ |
| 條件 | 受眾、版位、期間與預算 |
| 結果 | CTR、轉換率、成本與品質 |
| 限制 | 樣本、期間或其他干擾因素 |
| 下一步 | 保留、重測或提出新假設 |

長期累積下來，真正有價值的是你逐漸理解哪些訊息對哪些受眾有效，而不只是找到一張 CTR 特別高的圖片。
