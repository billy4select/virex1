文章寫完之後，通常還會再檢查一次標題、段落、圖片與連結。問題是，網路上有很多看似精準的 SEO 規則，例如標題要控制在某個字數、每篇一定要放幾條內部連結、每個 H2 都要有關鍵字。

這些數字可以當作提醒，卻不適合當成所有網站都必須遵守的標準。

我會把發布前檢查分成六個部分，先看內容是否解決問題，再看搜尋引擎能否正確理解頁面。

## 1. 這篇文章到底要回答什麼？

先用一句話寫下文章的主要任務。讀者看完後，應該能理解一個概念、完成一個操作，或做出一個選擇。

再確認搜尋結果中的主要頁型是否與你的內容方向相符。若搜尋者想比較方案，你卻只介紹概念，單靠修改標題很難補足內容落差。

## 2. 標題與描述是否清楚

標題應讓讀者知道頁面主題，以及點進去大致能得到什麼。避免只用「完整攻略」「必看技巧」等沒有具體資訊的詞。

檢查：
- 是否清楚描述文章主題？
- 是否和正文真正提供的內容一致？
- 是否有不必要的重複關鍵字？
- 是否容易與網站其他文章混淆？

Meta description 可以補充頁面重點，但搜尋引擎可能依查詢情況改寫搜尋摘要，所以不必把它當成一定會原樣顯示的廣告文案。

## 3. 內容結構能不能幫助閱讀

把 H2、H3 單獨抽出來看，應該能看出文章如何回答問題。標題要描述該段真正的內容，不要為了塞詞而重複同一個關鍵字。

同時確認：
- 開頭有沒有盡快進入主題？
- 重要答案是否容易找到？
- 步驟是否包含必要條件與限制？
- 表格、清單是否真的比文字更容易理解？
- 有沒有重複段落或與主題無關的延伸？

文章長度應由問題複雜度決定，沒有通用的最佳字數。

## 4. 內部與外部連結是否有用

內部連結可以帶讀者前往更完整的解釋、相關操作或下一個決策步驟。錨文字要讓人看得出連到哪裡，不要大量使用「點這裡」。

外部連結則應優先指向能支持事實、政策或操作說明的可靠來源。若內容會隨時間變動，確認來源仍有效。

不需要為了達到固定條數而硬加連結。每一條都應該有清楚用途。

## 5. 圖片與技術設定是否正常

- 圖片是否與段落內容相關？
- 替代文字是否描述圖片用途，而非堆疊關鍵字？
- 圖片是否有適當尺寸，避免載入過大的原始檔？
- 重要圖片是否因不必要的延遲載入而影響首屏？
- 網址、canonical、索引設定是否符合預期？
- 手機版是否能正常閱讀與操作？

結構化資料要依頁面實際內容選擇。不要為了追求搜尋結果的特殊呈現而標記頁面沒有提供的資訊，也不要把 Article、FAQ 或 HowTo 當成排名保證。

## 6. 發布後確認資料

發布後可以檢查網址是否能正常開啟，並透過 Search Console 觀察索引狀態、曝光、點擊與實際查詢。這些資料需要時間累積，不必在發布後幾小時就判斷成敗。

## 最後的快速清單

- [ ] 文章有明確的讀者任務。
- [ ] 頁型與搜尋需求大致相符。
- [ ] 標題與摘要沒有過度承諾。
- [ ] H2、H3 能呈現文章邏輯。
- [ ] 內容有回答問題，也交代限制。
- [ ] 內外部連結都能提供額外價值。
- [ ] 圖片、網址與索引設定正常。
- [ ] 發布後有安排合理的觀察方式。

這份清單的目的，是降低明顯疏漏。真正影響內容價值的，仍是你是否理解讀者的問題，以及文章是否提供了值得花時間閱讀的答案。
