# 專案工作流程 SOP

## 0. 基本資料
- 專案名稱：
- 交付對象：
- 截止日：
- 成功標準（一句話）：

## 1. 交付規格
- 形式與長度：
- 必備段落：
- 語氣：
- 絕對不能出現：

## 2. 角色與分工
| 角色 | 負責 | 不做 | 交付 |
| --- | --- | --- | --- |
| 專案經理 | 拆解、排順序、整合 | 不代替你決策 | 任務清單與交接規格 |
| 研究員 | 蒐集、整理來源 | 不寫結論 | 來源清單、重要發現、待確認 |
| 分析師 | 解讀資料、找洞察 | 不擴大範圍 | 洞察、證據、限制 |
| 企劃 | 提出方案 | 不編預算數字 | 方案、成本假設、風險 |
| 編輯 | 統整與改寫 | 不改觀點 | 完稿 |
| 品質檢查員 | 對照規格檢查 | 不重寫全文 | 問題清單與修正建議 |

## 3. 執行順序
1. 需求確認（你＋專案經理）
2. 蒐集（研究員）
3. 分析（分析師）
4. 提案（企劃）
5. 編輯（編輯）
6. 品管（品質檢查員）
7. 驗收（你）

## 4. 交接摘要（七欄）
1. 工作任務
2. 已完成的工作
3. 結果或分析
4. 資料來源
5. 重要發現
6. 尚未確認的資訊
7. 需要下一位完成的事

## 5. 檢查點
- 每個交接點：來源可打開／未確認有標記／格式無缺欄位
- 定稿前：事實、立場、對外風險

## 6. 常見錯誤與修正
- 來源打不開 → 只引用能打開的連結，附標題與日期
- 分析與研究重複 → 合併角色，交付改為洞察
- 編輯改寫過度 → 保留原句結構，不改觀點
- 品管流於形式 → 逐項對照交付規格，給通過／不通過

AI 名詞字典

只收錄入門會遇到的詞；解釋以白話為主，不追求技術細節。

名詞白話解釋什麼時候會用到
Prompt
提示詞		給 AI 的任務指令，通常包含角色、任務、限制與交付格式。每次下指令都會用到。
System prompt
系統提示		對話開始前設定角色與規則的指令，優先於一般對話。建立 AI 員工時。
Context window
上下文視窗		一次對話能容納的資訊量；超過之後，前面的內容可能被截斷。貼長文件或長對話時。
Token
詞元		模型計算長度的單位；實際換算依模型與語言而異。看到額度或長度限制時。
Hallucination
幻覺		AI 生成看似合理但不正確的內容，或編造來源。引用資料與數字時。
RAG
檢索增強生成		先檢索資料再生成回答，降低幻覺，但不保證正確。需要附來源的研究工作。
Agent
代理		會自行規劃步驟、呼叫工具的 AI；需要更清楚的邊界與檢查。進階自動化。
MCP
模型上下文協定		連接 AI 與外部工具、資料的協定。要讓 AI 直接讀取外部系統時。
Skills
技能模組		把一組能力與流程包成可重複使用的模組。重複執行同一類任務時。
API
應用程式介面		讓程式呼叫 AI 或服務的介面，通常需要金鑰。把 AI 接進自己的系統時。
Fine-tuning
微調		用特定資料調整模型行為；成本與維護較高。通用模型達不到需求時。
Temperature
溫度參數		控制輸出隨機性；低較穩定、高較發散。需要固定格式或發想時。
